# Store images in Cloudflare R2

imghost stores every image in a Cloudflare R2 bucket. With a custom domain connected to the bucket, image links point straight at that domain (for example `https://img.yoursite.com/aB3xK9pQ/photo.jpg`) and Cloudflare's CDN serves them from R2. The bytes never pass through your server, and R2 doesn't charge for egress.

You need a Cloudflare account and a domain on Cloudflare for the image hostname. Allow about 15 minutes.

## 1. Create the bucket

1. In the Cloudflare dashboard, open **R2 object storage → Create bucket**.
2. Name it, for example `imghost`. Leave the location on automatic, or pick the region closest to your users.
3. Pick a jurisdiction only if your data must stay in the EU; then set `R2_JURISDICTION=eu` later.

## 2. Connect the image domain

1. Open the bucket → **Settings → Custom Domains → Add**.
2. Enter a subdomain on a zone in the same Cloudflare account, such as `img.yoursite.com`, and connect it. Wait until the status is **Active**.
3. Leave the **Public Development URL** (`r2.dev`) disabled. It is rate-limited and meant only for testing.

Requests to this domain go through Cloudflare's cache, which caches image files by default.

**Recommended:** block raw uploads from being read on the public domain. Unprocessed uploads (still carrying EXIF data) live briefly under `uploads/` with unguessable names; a WAF rule closes that gap completely. In the zone, open **Security → WAF → Custom rules → Create rule**:

- Expression: `(http.host eq "img.yoursite.com" and starts_with(http.request.uri.path, "/uploads/"))`
- Action: **Block**

## 3. Create the API token

1. On the R2 overview page, under **Account Details**, choose **Manage** next to **API Tokens → Create Account API token**.
2. Choose a permission:
   - **Admin Read & Write** lets the setup script in step 5 configure CORS and lifecycle rules for you.
   - **Object Read & Write**, limited to this bucket, is the narrower choice. With it, set CORS and the lifecycle rule in the dashboard yourself (step 5 prints the exact settings).
3. Copy the **Access Key ID** and **Secret Access Key** now; the secret isn't shown again.
4. Copy your **Account ID** from the R2 overview page.

## 4. Set the variables

In `.env` (Docker Compose) or the service variables (Railway):

```
R2_ACCOUNT_ID=<account id>
R2_ACCESS_KEY_ID=<access key id>
R2_SECRET_ACCESS_KEY=<secret access key>
R2_BUCKET=imghost
R2_PUBLIC_URL=https://img.yoursite.com
UPLOAD_MODE=direct
```

Both the web app and the worker need the `R2_*` variables.

**Optional but recommended: instant removal from the CDN.** Without it, a deleted or removed image can stay in Cloudflare's cache for up to a day. With it, images are cached for a year and purged the moment they're deleted, expire or are removed by a moderator.

1. Under **My Profile → API Tokens → Create Token → Create Custom Token**, add the permission **Zone → Cache Purge → Purge** for the zone of `img.yoursite.com`.
2. Copy the **Zone ID** from that zone's overview page.
3. Set `CLOUDFLARE_ZONE_ID` and `CLOUDFLARE_API_TOKEN`.

## 5. Prepare the bucket

Run once after deploying:

```bash
# Docker Compose
docker compose exec app node dist/setup-bucket.js
# Railway
railway ssh --service web -- node dist/setup-bucket.js
```

It allows browser uploads from your `SITE_URL` (CORS) and makes R2 delete raw uploads after a day. If the token can't change bucket settings, it prints what to enter instead:

- **CORS:** bucket → **Settings → CORS Policy → Add CORS policy → JSON**:

  ```json
  [
    {
      "AllowedOrigins": ["https://yoursite.com"],
      "AllowedMethods": ["PUT", "GET", "HEAD"],
      "AllowedHeaders": ["content-type"],
      "ExposeHeaders": ["ETag"],
      "MaxAgeSeconds": 3600
    }
  ]
  ```

- **Lifecycle:** bucket → **Settings → Object lifecycle rules → Add rule**: prefix `uploads/`, delete objects 1 day after upload.

If you'd rather not set CORS at all, use `UPLOAD_MODE=server`; files then go through the app.

## 6. Check it

1. Upload an image on the site. Its direct link should start with `https://img.yoursite.com/`.
2. Open the link in a private window; the image should load.
3. Delete it from **My images**; the link should stop working (immediately if you set up cache purging).

## Moving existing images to R2

If you ran imghost before with MinIO, a Railway bucket or another S3 service, copy the images across once. Point the app at R2 as above, then run the migration with the old storage as the source:

```bash
SOURCE_S3_ENDPOINT=https://old-storage.example.com \
SOURCE_S3_BUCKET=old-bucket \
SOURCE_S3_ACCESS_KEY_ID=... \
SOURCE_S3_SECRET_ACCESS_KEY=... \
SOURCE_S3_REGION=auto \
SOURCE_S3_FORCE_PATH_STYLE=false \
node dist/migrate-storage.js --dry-run
```

Check the list, then run it again without `--dry-run`. It copies each image and its thumbnails into R2 and updates the database. It's safe to repeat: finished files are skipped. Existing links on your site (`https://yoursite.com/i/...`) keep working; they now forward to the R2 domain.

On Railway, run it with `railway ssh --service web -- env SOURCE_S3_...=... node dist/migrate-storage.js`, using the old bucket's credentials from its **Credentials** tab.

## Without a custom domain

Leave `R2_PUBLIC_URL` empty. Links then stay on your site (`https://yoursite.com/i/...`) and redirect to short-lived signed R2 URLs. Egress is still free, but Cloudflare's CDN doesn't cache the images, so a custom domain is faster.

## Costs

| Item | Price |
| --- | --- |
| Storage | $0.015 per GB-month (first 10 GB-month free) |
| Uploads and other writes (Class A) | $4.50 per million (first 1 million free each month) |
| Reads that reach R2 (Class B) | $0.36 per million (first 10 million free each month); CDN cache hits don't reach R2 |
| Egress | Free |
| Deletes | Free |

Each upload makes about four writes: the raw file, the processed original, and two thumbnails.
